# MyCW Rainbow Clock v2

นาฬิกา NTP + จอมอนิเตอร์หน้าร้านสำหรับ **Toy Station Plus+**
NodeMCU V2 (ESP8266) + จอ TFT 2.8" ILI9341

| ทำอะไรได้ | รายละเอียด |
|---|---|
| นาฬิกา NTP | ตั้ง WiFi จากมือถือ ย้ายสถานที่ได้โดยไม่ต้องคอมไพล์ใหม่ |
| ปุ่มสัมผัส | เปิด/ปิด/หรี่ไฟ + เรียก scene ของ Philips Hue |
| ยอดขาย 8 สาขา | ดึงจากระบบ TSP เดิม พร้อมธง **PENDING** ว่าสาขาไหนยังไม่ส่งรายงาน |
| OTA + หน้าเว็บ | อัปเดตเฟิร์มแวร์และตั้งค่าทุกอย่างจากมือถือ |

> **กฎเหล็ก:** ข้อความบนจอทุกตัวเป็น **English ASCII เท่านั้น** เพราะฟอนต์ของ
> TFT_eSPI ไม่รองรับการวางสระ/วรรณยุกต์ของภาษาไทย รายละเอียดเต็มใน
> [`../CLAUDE.md`](../CLAUDE.md) ข้อ 1

## 1. การต่อสาย

### 1.1 จอ ILI9341

| ขาจอ | NodeMCU | GPIO | หมายเหตุ |
|---|---|---|---|
| VCC | 3V3 | — | ห้ามต่อ 5V ถ้าโมดูลไม่มี regulator |
| GND | GND | — | |
| CS | D8 | 15 | |
| RESET | **ขา RST ของบอร์ด** | — | ทำให้ประหยัด GPIO ไป 1 ขา |
| DC / RS | D3 | 0 | |
| SDI / MOSI | D7 | 13 | |
| SCK | D5 | 14 | |
| LED / BLK | 3V3 | — | ดูข้อ 1.4 ก่อนคิดจะต่อเข้า GPIO |
| SDO / MISO | ไม่ต่อ | — | ต่อ D6 เฉพาะเมื่อจอมีทัชสกรีน |

### 1.2 ปุ่มสัมผัส TTP223 (โหมดหลัก)

ESP8266 **ไม่มี** วงจร capacitive touch ในตัว (ต่างจาก ESP32 ที่มี T0–T9)
จึงต้องใช้โมดูล TTP223 ภายนอก ตัวละ ~10 บาท ต่อโมดูลละ 3 เส้น

| TTP223 | NodeMCU | GPIO | ทำหน้าที่ |
|---|---|---|---|
| VCC | 3V3 | — | รับ 2.0–5.5V แต่ต้องใช้ 3.3V ให้ logic ตรงกับบอร์ด |
| GND | GND | — | |
| I/O | D1 | 5 | **ปุ่ม A** |
| I/O | D2 | 4 | **ปุ่ม B** (โมดูลตัวที่ 2) |

**จั๊มเปอร์บนโมดูล — ตั้งผิดแล้ว gesture พังทั้งระบบ**

| จั๊มเปอร์ | ต้องเป็น | ถ้าบัดกรี |
|---|---|---|
| A | **ไม่บัดกรี** (ค่าจากโรงงาน) | กลายเป็น toggle/latch → **ตรวจ long-press ไม่ได้เลย** |
| B | **ไม่บัดกรี** | กลายเป็น active LOW → ปุ่มจะทำงานกลับด้าน |

**ข้อควรระวัง**
- เอาต์พุตเป็น push-pull 3.3V ต่อเข้า GPIO ตรงได้ ไม่ต้องมี resistor
- สาย GPIO ↔ โมดูล **ไม่ควรเกิน 20 cm** ยาวกว่านั้นให้ย้ายโมดูลไปติดใกล้
  แผ่นสัมผัส แล้วเดินสาย 3 เส้นกลับมาที่บอร์ด
- แผ่นสัมผัส: ทองแดง/ฟอยล์ ~15×15 mm ติดหลังอะคริลิก **หนาไม่เกิน 3 mm**
- ไวเกินจนกระตุกเอง → บัดกรี cap 10–50 pF คร่อมขา sensor กับ GND
- ถ้าจะถอดโมดูลออกชั่วคราว ให้ใส่ R 100 kΩ จาก GPIO ลง GND กัน event ผี
  (ขาลอยจะอ่านค่ามั่ว)
- กินไฟ standby ~3 µA ไม่กระทบงบไฟ

### 1.3 ทางเลือก — จอที่มีทัชสกรีน XPT2046 ในตัว

ถ้าจอมีขาเพิ่มอีก 5 ขา (T_CLK / T_CS / T_DIN / T_DO / T_IRQ) ให้ uncomment
บรรทัด `#define USE_XPT2046` ใน `config.h` แล้วต่อตามนี้ — **ไม่ต้องใช้ TTP223**

| XPT2046 | NodeMCU | GPIO |
|---|---|---|
| T_CLK | D5 | 14 (ใช้ SPI ร่วมกับจอ) |
| T_DIN | D7 | 13 (ร่วม) |
| T_DO | D6 | 12 |
| T_CS | D2 | 4 |
| T_IRQ | D1 | 5 |

โหมดนี้แบ่งครึ่งจอ: แตะครึ่งซ้าย = ปุ่ม A, ครึ่งขวา = ปุ่ม B

### 1.4 ไฟเลี้ยง — สาเหตุอันดับ 1 ที่บอร์ดรีบูตเอง

- ESP8266 กระชากถึง ~300 mA ตอนยิง WiFi + backlight จอ ~70 mA
  → **ใช้อะแดปเตอร์ 5V 1A ขึ้นไป ไม่ใช่พอร์ต USB ของคอม**
- ใส่ **C อิเล็กโทรไลต์ 470 µF + เซรามิก 0.1 µF** คร่อม 3V3–GND
  ให้ใกล้ขาจอที่สุด กัน brownout ตอน TX
- **ห้ามต่อ backlight เข้า GPIO ตรง ๆ** GPIO ของ ESP8266 จ่ายได้แค่ ~12 mA
  แต่ backlight กิน ~70 mA ขาจะพัง ถ้าจะทำ PWM หรี่จอต้องใส่
  N-MOSFET (AO3400 / 2N7000) หรือ NPN (S8050) คั่น โดยขา gate/base ต่อ D4 (GPIO2)

## 3. ใช้งานครั้งแรก

1. อัปโหลดเฟิร์มแวร์ 1 ครั้งผ่าน USB
2. จอขึ้นหน้า **WIFI SETUP** พร้อมรหัสเว็บ 6 หลัก (`WEB PIN`) — จดไว้
3. เอามือถือต่อ WiFi ชื่อ `RainbowClock` รหัส `12345678`
4. หน้าเว็บตั้งค่าจะเด้งขึ้นเอง → Configure WiFi → เลือกเครือข่าย → ใส่รหัส → Save
5. นาฬิกาต่อเน็ตแล้วเด้งกลับมาแสดงเวลา
6. เปิด `http://mycw.local` บนมือถือ (user `admin` / รหัส 6 หลักจากข้อ 2)

### เปลี่ยน WiFi ภายหลัง
- **แตะปุ่ม A ค้าง 1.5 วินาที** หรือ
- **กดปุ่ม RESET บนบอร์ด 2 ครั้ง** (ครั้งที่สองภายใน 6 วินาที)
  *ใช้ได้กับปุ่ม RESET เท่านั้น การถอดปลั๊กเสียบใหม่ไม่ทำงาน เพราะ RTC memory
  หายเมื่อไฟดับสนิท*
- หรือกด **Forget WiFi** ในหน้าเว็บ

ถ้าปล่อยไว้ 5 นาทีไม่ได้ตั้งค่า เครื่องจะรีสตาร์ตแล้วลองต่อ WiFi เดิมเอง ไม่ค้าง

### WiFi ที่ต่อไม่ได้
ESP8266 ต่อได้เฉพาะ WPA/WPA2-PSK แบบใส่รหัสผ่านธรรมดา **ต่อไม่ได้** ถ้าเป็น
WPA2-Enterprise (login ด้วย user/password), captive portal แบบโรงแรม,
หรือ WiFi 5GHz อย่างเดียว — ทางออกง่ายสุดคือเปิด hotspot จากมือถือ

## 4. ตั้งค่า Philips Hue

1. เปิด `http://mycw.local` → **Find bridge** (ค้นด้วย mDNS ใน LAN ไม่ผ่านคลาวด์)
   ถ้าหาไม่เจอให้กรอก IP เอง (Hue app → Settings → Bridge)
2. กด **Pair with bridge** → จอนาฬิกาจะนับถอยหลัง 30 วินาที
3. **กดปุ่มกลมบน Hue Bridge** ภายในเวลานั้น
4. จอขึ้น `HUE PAIRED` แล้วสลับไปหน้า LIGHTS อัตโนมัติ

username token ถูกเก็บใน `/config.json` บนแฟลช **ไม่มีอยู่ในซอร์สโค้ด**

หน้า SYSTEM จะบอกว่าบริดจ์ของคุณใช้ **API v1 หรือ v2** — โค้ดลอง v1 ก่อนเพราะ
เบาและเร็วกว่ามาก (HTTP ธรรมดา ~50–150 ms) ถ้าบริดจ์ปิด v1 ไปแล้วจะสลับไป v2
(HTTPS ~300–600 ms) อัตโนมัติและจำไว้

**Scene A / B** ใส่ scene id ในหน้าเว็บ (หาได้จาก
`http://<bridge-ip>/api/<username>/scenes` บนเบราว์เซอร์)

## 5. ตั้งค่ายอดขาย

ดูขั้นตอนเต็มใน [`apps_script/clock_action.gs`](apps_script/clock_action.gs)
สรุปสั้น ๆ:

1. เพิ่มคอลัมน์ `Short_Name` (อักษรละติน ≤ 10 ตัว) ท้ายชีต `Branches`
2. วาง patch 2 บล็อกเข้า Code.gs ของ Apps Script **"webapp tsp meter"**
3. ตั้ง Script Property `CLOCK_TOKEN`
4. ตั้ง time-driven trigger `warmClockCache` ทุก 5 นาที
5. Deploy version ใหม่ (URL `/exec` เดิม)
6. ใส่ URL + token ในหน้าเว็บของนาฬิกา

> ยอดทั้งหมดคำนวณโดย `meterAll_()` / `isRevOk_()` ตัวเดียวกับที่ Dashboard และ
> AppSheet ใช้ **ห้ามคำนวณซ้ำฝั่งนาฬิกา** ไม่งั้นตัวเลขจะไม่ตรงกัน

ถ้าดึงข้อมูลไม่สำเร็จ จอจะคง **ตัวเลขเดิม** ไว้แล้วขึ้น `STALE HH:MM` สีเหลือง
จะไม่โชว์เลข 0 เด็ดขาด เพราะอ่านแล้วเข้าใจผิดว่าวันนี้ขายไม่ได้

| หน้า | แสดงอะไร |

| **CLOCK** | เวลาไล่สีรุ้ง, วันที่, เลขสัปดาห์ ISO (W38), ยอดรวมวันนี้, จำนวนสาขาที่ยังไม่ส่ง |

## 8. ตรวจสอบหลังติดตั้ง

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | Verify ใน IDE | คอมไพล์ผ่าน, `Global variables` เหลือ heap ว่าง > 30 KB |
| 2 | บูตครั้งแรก | เข้าโหมด AP `RainbowClock` + จอโชว์ WEB PIN |
| 3 | ต่อ WiFi | เวลาตรง, `W38` ตรงกับปฏิทินจริง, เข้า `http://mycw.local` ได้ |
| 4 | ปุ่มสัมผัส | Serial Monitor (115200) ขึ้น `[touch] event N` ครบทุกท่า ไม่มี event ผี |
| 5 | Hue pair | หน้า SYSTEM บอกว่าใช้ API v1 หรือ v2 |
| 6 | Hue control | ปุ่ม B → ไฟติด/ดับจริงใน ~1 วินาที |
| 7 | `clock` action | เปิด URL บนเบราว์เซอร์ → JSON 8 สาขา **ยอดตรงกับ Dashboard** |
| 8 | หน้า SALES | ตัวเลขตรงกับข้อ 7, ไม่มีตัวอักษรเพี้ยน/กล่องสี่เหลี่ยม |
| 9 | ถอดเน็ต | ขึ้น `STALE` ไม่ใช่เลข 0 |
| 10 | OTA | อัปโหลด `.bin` ที่ `/update` แล้วรีบูตด้วยเวอร์ชันใหม่ |
| 11 | **Soak 24 ชม.** | หน้า SYSTEM: **HEAP ต้องนิ่ง** ไม่ไหลลงเรื่อย ๆ, UPTIME ไม่รีเซ็ตเอง |

ข้อ 7 คือด่านสำคัญ ถ้ายอดไม่ตรง Dashboard แปลว่า patch ผิด ต้องแก้ก่อนไปต่อ
ข้อ 11 สำคัญไม่แพ้กัน heap leak จาก TLS คือสาเหตุอันดับ 1 ที่ ESP8266
รีบูตเองทุก 2–3 ชั่วโมง

## 9. ความปลอดภัย

- **ไม่มี secret ในซอร์สโค้ด** — WiFi อยู่ใน flash ของ WiFiManager,
  Hue token / URL / CLOCK_TOKEN / รหัสหน้าเว็บ อยู่ใน `/config.json` บน LittleFS
  ซึ่งถูกกันไว้ใน `.gitignore` แล้ว
- หน้าเว็บบังคับ HTTP Basic Auth ทุก endpoint เพราะเครื่องอยู่บนเน็ตเวิร์กร้าน
  รอบแรกสุ่มรหัส 6 หลักแล้วแสดงบนจอ — คนที่เห็นจอเท่านั้นถึงจะเข้าได้
  **ควรเปลี่ยนเป็นรหัสของตัวเองในหน้าเว็บ**
- การเชื่อมต่อ Hue เป็น local LAN ล้วน ไม่ผ่านคลาวด์ ใช้งานได้แม้เน็ตนอกบ้านล่ม
- การดึงยอดขายใช้ `setInsecure()` (ไม่ตรวจ cert) เพราะ root CA ของ Google
  หมุนเวียนบ่อยเกินกว่าจะ pin ไว้ในเฟิร์มแวร์ ชดเชยด้วย `CLOCK_TOKEN`
  และฝั่งเซิร์ฟเวอร์เป็น read-only ส่งแต่ยอดสรุป ไม่มีข้อมูลพนักงานหรือลูกค้า
